# SKÄRMRO Privacy policy

SKÄRMRO follows the principle **Boundary, not surveillance**.

This document describes the intended data handling of the open-source SKÄRMRO Windows application. It must continue to match the behavior of released builds.

## Data SKÄRMRO does not intentionally collect

SKÄRMRO is not designed to collect or transmit:

- keystrokes;
- screen recordings;
- private messages;
- passwords;
- camera or microphone content;
- complete viewing history;
- complete web-browsing history.

## Local data

SKÄRMRO may store configuration and protection state locally on the Windows computer, including:

- parental protection settings;
- blocked channels;
- custom blocked words or phrases;
- routines;
- application rules;
- temporary-access overrides;
- Policy Receipts;
- anonymous local counters for protection/filter categories.

Policy Receipts are intended to describe what the protection system did, rather than preserve the child's detailed browsing content.

## Network communication

SKÄRMRO itself will not transfer personal information to SKÄRMRO-operated networked systems unless that functionality is specifically requested or enabled by the user or person installing/operating the software.

Normal use of third-party applications and websites, such as Google Chrome and YouTube, is subject to those third parties' own network behavior and privacy policies.

The current Gate 0 architecture does not require a SKÄRMRO cloud service for Browser Guard policy storage.

If cloud synchronization or telemetry is introduced later, this policy must be updated before that functionality is released.

## Security and local privileges

Native SKÄRMRO protection components may run with elevated Windows privileges where required for enforcement. Protected policy state is kept separate from child-readable launcher state.

## Changes

Material privacy changes must be documented with the release that introduces them.
